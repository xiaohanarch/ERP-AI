01这个项目是什么

企业把 LLM 接进 ERP 时会遇到几类反复出现的问题：数据权限口径不一致、Agent 影子接入 无法治理、AI 的答案事后查不清、一次误写造成不可逆损失。本项目用一个应付（AP）模块的 仿真存量系统，把总纲给出的应对方案逐一做成机制并验证。下面每张卡片都可以点进在线演示 （登录账号见 05 节）：

事故可复现 scene_1

同一份数据三种口径：ERP 页面约 50 条（组织过滤）、Open API 5000+ 条（租户级，事故口径）、 BO API 与页面共享同一个 PermissionService 并披露过滤维度。两边结果一致 靠的是同一个权限组件，不靠提示词约束。

▶ 在线演示： ERP 页面（zhangsan 登录看 ~50 条） · 问 AI（同权限口径 + 披露）

判定不靠模型自觉 scene_3/4

未注册、已吊销、超范围、SoD 互斥，都在网关拦截链拒绝（六个独立错误码）； 诱导话术在进图之前就被护栏拦下，不会有任何工具调用抵达 BO API。这些判定 在网关和存量域完成，模型输出不参与。

▶ 在线演示： 诱导话术（看它被拦在哪里） · 未注册/吊销（脚本幕）

不可逆即审批 scene_6

税码变更在规格里标记为不可逆，因此强制走审批：挂起期间不持有任何常驻凭据， 批准后铸造一次性令牌 OT（绑定参数指纹、120 秒、只能用一次），唤醒重发走两层幂等， 全程留痕，可导出证据包。

▶ 在线演示： 发起税码变更（lisi） · 审批台三要素（wangwu）

双租同题不同答 scene_5

同一句「大额风险」，T-EAST 按 50 万口径命中、T-UNI 按 500 万口径命中； 「进货单」一边解析为采购订单、一边解析为收货单。口径差异放在语义叠加层， 两边各答各的，数据互不可见。

▶ 在线演示（同一链接，换账号登录）： 大额筛查：lisi 命中 INV-A-011 / qianqi 命中 INV-B-004

不完整必披露 scene_2

没有预算权限的用户查发票，存量系统的行为是静默跳过预算规则组；BO API 适配层 改为在响应里声明 completeness.full=false + skippedRuleGroups—— 不泄露预算发现本身，但明确告诉提问者有一步没有跑。

▶ 在线演示（同一问题，不同人不同答案）： zhangsan 见「预算校验未执行」/ lisi 见预算超支发现

一次采集两用 Jaeger

OTel GenAI 风格 span 树（invoke_agent→chat→execute_tool）带六组扩展字段： 身份 / 版本四件套 / 场景 / 完整性 / 动作性质 / 内容摘要；成本台账按租户×Agent×场景×用户四维计量，与审计对账。

02十四条架构判断（这个仓库在回答什么）

这个仓库由 14 条架构判断驱动，路线是 AI-Native，不是在 ERP 上外挂 AI。 每一条判断在下表里都有对应的机制落点和可重复执行的验证入口； 与业界判据的完整对照（含张力分析）见 docs/architecture-alignment.md。

#判断本仓落点（机制）验证状态
1AI-Native，不是 ERP + AI 底座优先：AI 动作全走 T2/T3 + BO 合同 + 存量校验/幂等/审计，无平行权限体系；三口径对照证明「页面能看的 AI 也能看」 scene_1 三口径 ✅
2传统 ERP = SoR + 确定性执行 Java 存量域：事务 + 业务幂等（同键重放首次结果）+ 稳定错误码；AI 只经 BO 合同进入，不绕过 scene_6 幂等重放✅
3AI 是 ERP 内生组成部分 内生 = 共享同一套本体/权限/审计与幂等（底座式），而非进程同体；BO 工具与页面同权限组件 PermissionParityTest✅
4Ontology = 统一语义模型 + 逻辑核心 语义三段式（投影/增量/原生）= 统一语义与校验核心（术语/指标/规则/护栏/能力问题唯一真相源）；「结构生成核心」为阶段二愿景 scene_5 + 漂移检测⚠️ 分阶段
5Metadata 是 Ontology 的输入与来源 投影段实时取存量元数据；漂移检测把「本体引用与元数据一致」做成可检验不变式（预埋漂移必检出） drift_check.py✅
6多领域 Agent + 协同组合 AP × 采购跨域委派：注册表协作清单 + act 委托链增长 + 子代理最小权限 T2；清单外委派 403 scene_8 跨域诊断 ✅
7业务执行：Agent → API → 微服务 → 事务 hub 场景图 → 网关 MCP 代理 → Java BO API → 数据库事务；Jaeger 全链 trace 顶部「读路径」动画✅
8流程以预定义为主，不要求自适应 LangGraph 图静态装配；模型只按动作契约（CONTRACTS）填意图与参数，不自主规划路径 hub/graphs/*✅
9业务规则：AI 可理解使用、不可修改 护栏三层解析只加严（放松被拒）+ 解析留痕；规则经语义工具供理解；不存在任何写规则的模型工具 scene_3 + 解析查看器 ✅
10触发：Open API / Event / Scheduler 形态③无头（API）、形态④事件（outbox→Agent）、形态⑤定时（scheduler→Agent） scene_7✅
11人：执行者 → 确认者 / 例外处理者 / 监督者 审批台（三要素+快照+参数指纹）、挂起/唤醒（例外）、解析查看器 + 审计五要素 + 四问自检 + 成本对账（监督） scene_6 + E2E 19 项✅
12Agent 演进：先协同传统，终局替换部分执行 现处协同阶段；治理面（T3/审批/幂等/审计）执行端无关——替换发生时管控面零改动（架构对冲） token-design.md✅ 阶段一
13产品化：标品 core + Metadata/Ontology/配置适配 三层 harness：Standard → Partner（制造业行业包）→ Tenant；租户/行业配置有管理端界面，改完即生效（文件层为出厂默认，变更留痕），scene_10 scene_7 / scene_10 + 租检 37/37✅
14SaaS：标品层/租户层隔离，API / Message 扩展 跨租隔离 + 成本对账；BO API 扩展（规格即工具）+ 消息订阅（topic × webhook × HMAC，按租户隔离投递出平台，吊销即停） scene_9 + tenant_checks✅

三个张力点（判断之间需要表态的地方）

A · 内生 vs 旁挂拓扑

本仓拓扑是「Python 底座 + Java 存量」两套栈。判断「内生」的依据是管控复用： AI 与页面共享同一套权限、审计与幂等（三口径可以验证），而不是进程同体。 底座优先是 AI 原生的一条合法路线。

B · Ontology 的方向性

判断 4（本体是逻辑核心）与判断 5（元数据是本体来源）之间存在张力：从元数据 推导出的本体只是一面镜子。本仓的表述是分阶段的：先做统一语义与校验核心 （已达成），结构生成核心留给阶段二。

C · 替换终局的对冲

判断 12 的终局（替换部分传统执行）如何与判断 2（存量确定性）兼容？答案在于 治理面放在网关与合同层而不在 Java：执行端换成任何实现，只要履行同一个 BO 合同， 管控面不需要改动。

两条升格（本仓有、而 14 条没有的）

15 · 可验证性是一等公民

50 条锚点评测分六类，其中幻觉与诱导是两个负向类；30 条能力问题与评测用例 同源绑定；mock/replay/live 三态可按请求钉定。护栏本身也在被评测的范围内。

16 · 口径互证作为治理基础设施

三口径权限对照、成本台账与审计对账、四问自检，构成「监督者」角色需要的 数据基础设施，全部自动化、可复跑。

逐跳收窄

T1[chat] → T2[场景∩清单] → T3[单工具 60s] → OT[单工具+参数指纹 120s]
每跳权限是上一跳的子集，act 委托链单调增长，进审计与 trace。 详见 令牌设计。

权限只在存量域

T3 进 Java 后走与页面同一个 PermissionService（租户/公司/组织三维）。 AI 链路不做任何权限计算，对齐由 PermissionParityTest 保证。

三层 harness

Standard → Partner → Tenant 确定性解析。Partner 层已落地制造业行业包（行业术语与 行业护栏，按租户行业声明匹配）；只有标记 overridable 的资产可被覆盖， 护栏只能加严，放松类叠加会被拒绝。解析查看器展示每次运行用了哪层哪版本。

多领域 Agent 协同 scene_8

跨域归因走显式委派：ap-copilot 在注册表协作清单（delegates_to）里声明 proc-copilot， 网关 exchange 做第七道校验（清单外 403）；子代理用自己的 T2 执行，权限最小， act 委托链 [proc → ap → hub] 经 T3 贯穿到存量域审计。

▶ 在线演示： 跨域诊断：AP 归因 + 采购取证 → 供应商超开结论

Message 扩展 scene_9

租户通过消息订阅把领域事件接进自己的系统，不需要改动标品核心：注册 （topic × webhook × 签名密钥）后，事件按（租户 × topic）隔离投递出平台， 带 HMAC-SHA256 签名、逐次审计、吊销即停。与形态④互补：一个是事件进 Agent， 一个是事件出平台。

▶ 在线演示： python scripts/demo/scene_9.py（本机起租户 webhook 接收器，现场看隔离投递）

配置即数据 scene_10

租户与行业配置有管理端界面：改大额阈值、切行业、调术语，保存即生效， 不需要重启或重建镜像。文件层是出厂默认，管理端写入 DB 层（首次写入时从文件 播种），「恢复出厂」回落文件层；每次变更记 who/when/what。

▶ 在线演示： 租户配置页（wangwu 登录） · 改完阈值回对话页立即验证口径
