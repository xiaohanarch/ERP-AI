01这个项目是什么

企业把 LLM 接进 ERP 时反复撞上的问题：数据权限口径不一致、Agent 影子接入无法治理、 AI 的答案没人能审计、一次误写就造成不可逆损失。本项目用一个应付（AP）模块的仿真存量系统， 把总纲给出的答案逐一落成机制并验证。每张卡片都可以点进在线演示（登录账号见 04 节）：

事故可复现 scene_1

同一份数据三种口径：ERP 页面 ~50 条（组织过滤）、Open API 5000+ 条（租户级、事故口径）、 BO API 与页面共享同一个 PermissionService 并披露过滤维度。「页面能看的 AI 也能看」是机制，不是约定。

▶ 在线演示： ERP 页面（zhangsan 登录看 ~50 条） · 问 AI（同权限口径 + 披露）

判定不靠模型自觉 scene_3/4

未注册 / 已吊销 / 超范围 / SoD 互斥全部在网关拦截链拒绝（六个独立错误码）； 诱导话术被护栏在进图之前拦下，零工具调用抵达 BO API。提示词注入改变不了判定结果。

▶ 在线演示： 诱导话术（看它被拦在哪里） · 未注册/吊销（脚本幕）

不可逆即审批 scene_6

税码变更（规格标记 irreversible）强制审批：挂起期零常驻凭据，批准铸一次性令牌 OT （参数指纹绑定、120 秒、只能用一次），唤醒重发走两层幂等，全程留痕可导出证据包。

▶ 在线演示： 发起税码变更（lisi） · 审批台三要素（wangwu）

双租同题不同答 scene_5

「大额风险」T-EAST 按 50 万口径命中、T-UNI 按 500 万口径命中；「进货单」一边解析为采购订单、 一边解析为收货单；余额指标各按各的口径。语义叠加层让同一句提问得到各自正确的答案，互不泄露。

▶ 在线演示（同一链接，换账号登录）： 大额筛查：lisi 命中 INV-A-011 / qianqi 命中 INV-B-004

不完整必披露 scene_2

无预算权限的用户查发票，存量行为是「静默跳过规则组」；BO API 适配层改为 completeness.full=false + skippedRuleGroups 披露——不泄露发现本身，也绝不假装结论完整。

▶ 在线演示（同一问题，不同人不同答案）： zhangsan 见「预算校验未执行」/ lisi 见预算超支发现

一次采集两用 Jaeger

OTel GenAI 风格 span 树（invoke_agent→chat→execute_tool）带六组扩展字段： 身份 / 版本四件套 / 场景 / 完整性 / 动作性质 / 内容摘要；成本台账按租户×Agent×场景×用户四维计量，与审计对账。

▶ 在线演示： Jaeger 里看真实 trace（先点上面任意对话产生一条）

逐跳收窄

T1[chat] → T2[场景∩清单] → T3[单工具 60s] → OT[单工具+参数指纹 120s]
每跳权限是上跳子集，act 委托链单调增长，进审计与 trace。详见 令牌设计。

权限只在存量域

T3 进 Java 后走与页面同一个 PermissionService（租户/公司/组织三维）。 AI 链路零权限计算——权限对齐由 PermissionParityTest 保证。

三层 harness

Standard → Partner → Tenant 确定性解析；Partner 层已落地制造业行业包（行业术语 + 行业护栏，按租户行业声明匹配，不跨行业串扰）；仅 overridable 资产可覆盖， 护栏只加严（放松类叠加被拒），WorkBuddy 解析查看器可视化每次运行用了哪层哪版本。

04如何使用

1

一键启动（Docker Desktop / WSL2）

无需模型 API key——开箱默认 MODEL_MODE=mock（脚本化确定性应答）。首次构建约 2-4 分钟（含 Java + Flyway 迁移 + 种子）。

# 在仓库根目录
cd compose
docker-compose up -d --build
docker-compose ps          # 全部 Up/healthy 后（约 30-60 秒）即可验证

想接真实模型：复制 compose/.env.example 为 compose/.env，设 MODEL_MODE=live 与 LIVE_*。 协议两选一：LIVE_PROTOCOL=openai（DeepSeek / GLM / Qwen 的 OpenAI 兼容端点）或 LIVE_PROTOCOL=anthropic（Anthropic Messages 兼容端点，本演示机当前即以 GLM-5.3 经此协议接入）。 切 live 后评测与演示脚本仍保持确定性——它们按请求钉定 X-Model-Mode: mock，只有交互面（WorkBuddy / ERP 页面）走真实模型。
