ERP-AI
把 ERP AI 架构总纲做成能跑、能验、能审计的工程

依据 14 章《ERP AI 技术架构总纲》构建的可运行参考实现：一条真实链路 「用户 → AI 网关 → Agent → BO API → Java 存量应付模块」， 复现「页面 50 条 vs Open API 5000 条」权限事故，50 条评测用例全绿， 双租户六项检验全过。不是 PPT——每个主张都有代码落点与可重复执行的断言。

评测 50/50 通过 多租六项 37/37 双租户 T-EAST / T-UNI 四种 Agent 形态 docker-compose 一键起 零模型 key（mock/replay）

01这个项目是什么

企业把 LLM 接进 ERP 时反复撞上的问题：数据权限口径不一致、Agent 影子接入无法治理、 AI 的答案没人能审计、一次误写就造成不可逆损失。本项目用一个应付（AP）模块的仿真存量系统， 把总纲给出的答案逐一落成机制并验证：

事故可复现 scene_1

同一份数据三种口径：ERP 页面 ~50 条（组织过滤）、Open API 5000+ 条（租户级、事故口径）、 BO API 与页面共享同一个 PermissionService 并披露过滤维度。「页面能看的 AI 也能看」是机制，不是约定。

判定不靠模型自觉 scene_3/4

未注册 / 已吊销 / 超范围 / SoD 互斥全部在网关拦截链拒绝（六个独立错误码）； 诱导话术被护栏在进图之前拦下，零工具调用抵达 BO API。提示词注入改变不了判定结果。

不可逆即审批 scene_6

税码变更（规格标记 irreversible）强制审批：挂起期零常驻凭据，批准铸一次性令牌 OT （参数指纹绑定、120 秒、只能用一次），唤醒重发走两层幂等，全程留痕可导出证据包。

双租同题不同答 scene_5

「大额风险」T-EAST 按 50 万口径命中、T-UNI 按 500 万口径命中；「进货单」一边解析为采购订单、 一边解析为收货单；余额指标各按各的口径。语义叠加层让同一句提问得到各自正确的答案，互不泄露。

不完整必披露 scene_2

无预算权限的用户查发票，存量行为是「静默跳过规则组」；BO API 适配层改为 completeness.full=false + skippedRuleGroups 披露——不泄露发现本身，也绝不假装结论完整。

一次采集两用 Jaeger

OTel GenAI 风格 span 树（invoke_agent→chat→execute_tool）带六组扩展字段： 身份 / 版本四件套 / 场景 / 完整性 / 动作性质 / 内容摘要；成本台账按租户×Agent×场景×用户四维计量，与审计对账。

★ 规格真源 boapi-spec/bo-ap.yaml（OpenAPI 3.1 + x-bo-extensions）——MCP 工具定义、 网关注册表、评测期望、语义投影全部由它派生；改规格 → 版本戳变更 → 录制作废 → 评测重跑。

逐跳收窄

T1[chat] → T2[场景∩清单] → T3[单工具 60s] → OT[单工具+参数指纹 120s]
每跳权限是上跳子集，act 委托链单调增长，进审计与 trace。

权限只在存量域

T3 进 Java 后走与页面同一个 PermissionService（租户/公司/组织三维）。 AI 链路零权限计算——权限对齐由 PermissionParityTest 保证。

三层 harness

Standard → Partner → Tenant 确定性解析；仅 overridable 资产可覆盖， 护栏只加严（放松类叠加被拒），WorkBuddy「解析查看器」可视化每次运行用了哪层哪版本。

04如何使用

1

一键启动（Docker Desktop / WSL2）

无需模型 API key——默认 MODEL_MODE=mock（脚本化确定性应答）。首次构建约 2-4 分钟（含 Java + Flyway 迁移 + 种子）。

# 在仓库根目录
cd compose
docker-compose up -d --build
docker-compose ps          # 全部 Up/healthy 后（约 30-60 秒）即可验证

想接真实模型（OpenAI 兼容：DeepSeek / GLM / Qwen）：复制 compose/.env.example 为 compose/.env， 设置 MODEL_MODE=live 与 LIVE_* 后重启。
